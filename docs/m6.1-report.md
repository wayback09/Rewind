# M6.1 Report — Archaeology & Validation

> Goal: *Find unknowns that could force redesign of Scene before M7.* — **ACHIEVED**. No renderer started, only evidence-backed small fixes.

## 1. Executive Summary

M6.1 investigated four high-risk unknowns via actual 26.2 JAR (`39,193,383` bytes), actual `assets/minecraft/blockstates/*.json` (1,199) + `models/block/*.json` (2,658), actual registry `26.2-blocks-array.json` (32,366 states), actual Flashback source (`Flashback-0.43.3-for-MC26.2.jar` ordering), and actual recordings (916t, 2242t, 2341t).

**Key findings:**

- **Block models:** `CanonicalBlockState {name, properties: BTreeMap}` is sufficient, but `waterlogged` must be stripped for stairs/slabs/fences etc., and a single state can resolve to **multiple** `multipart` models with `x/y/uvlock`. M6's single `AssetRef` is insufficient for multipart. **Small change:** introduce `BlockModelRef {key,x,y,uvlock,weight,asset}` and `block_models() -> Vec<>` (backwards compatible).
- **Block entities:** Numeric `type_id` VarInt in `level_chunk_caches` is **not** symbolic; NBT `id` absent for 88% of sculk BEs (`{}`), so registry order is required. M6 stored `minecraft:block_entity_type_34` → `Unsupported`. **Small change:** embed 26.2 `BlockEntityType` table (49 entries, 0=FURNACE … 34=SCULK_SENSOR 43=TRIAL_SPAWNER 44=VAULT) so `type_name` becomes symbolic and `StubAssetProvider` can return `Known`.
- **game_packet 101:** **CONFIRMED** `ClientboundSetEntityMotionPacket` (`VarInt eid + LpVec3`) — 24,393 occurrences (63% of replay `game_packet`), 47-71% per recording, 3787 in `basic/test_recording.zip`. It is **entity-velocity, not chunk**, thus **scene-affecting but non-chunk** (interpolation). M6 preserved it as `unknown`. **Small change:** decode `LpVec3` (1-byte zero or 6-7-byte packed) in `playback` and expose `CanonicalEntity.velocity` → `SceneEntity.velocity` (included in fingerprint/diff).
- **Unknown actions:** Most frequent are `game_packet` non-dimension packets (101 now handled, remaining 99,1,84,77 etc. are entity/block updates still preserved). `configuration_packet` 32 per snapshot (metadata), `real_time_clock`/`voice`/`accurate` are **A/B definitely irrelevant** (0 occurrences for voice/accurate). No currently ignored action mutates **chunks** except `level_chunk_cached` which is already applied. No RED blocker.
- **Scene API:** After above, `Scene` contains everything M7 needs without reaching into `playback` (blocks via `CanonicalBlockState`, models via `BlockModelRef`, entities with velocity, block entities symbolically, dimension/environment, lighting/biome `RawPreserved`). Lighting/biome remain safely abstracted for later improvement.

**M7_READY = YES** (with 3 small changes applied, documented below).
